## 1. 产品定位与设计原则

**定位**：Flameshot 15.0 的 Windows 二次开发 fork，核心增量是**滚动截图（自动滚动 + 拼接即出图）**，辅以序号标注增强、热键体系、稳定性守护与自制安装器。单机桌面工具，无云端依赖。

### 六条设计铁律（所有改动都要对齐，违背需在 [[实施记录]] 写明理由）

1. **不静默失败**。凡是"可能不完美"的输出必须显式标注：拼接三态（MATCHED / NO_CHANGE / FAILED）、质量徽章绿/黄/红、`degraded` 接缝计数、上限截断提示。反面教材是 v1 的静默腰斩（见 [[滚动截屏调研]] §4 第 5 条）——用户拿到一张看似正常实则错位的图，比报错更糟。
2. **物理正确性优先**。所有坐标、裁剪、拼接都在**物理像素层**运算（`clientRectOf` 客户区裁剪、DPR 复位 1.0、虚拟桌面全局坐标）；逻辑坐标只用于 UI 文本。高 DPI / 多屏混合是设计前提不是补丁。
3. **优雅降级链**。任何能力都按"最优→次优→兜底"排列：滚动注入 滚轮→下箭头→PageDown→WM_MOUSEWHEEL 消息；容器探测 UIA→像素侧栏检测；实例退出 `quit` 动词→6s 轮询→强杀兜底。链条每一环都可独立验证。
4. **全程用户可见、可中止**。选区→确认→采集每一步都有 HUD/高亮框反馈，Esc 随时退出。采集用 SendInput 异步注入，不装钩子、不独占输入。
5. **轻依赖**。SPEC 冻结「纯 QImage，不引入 OpenCV」；安装器纯 Win32 只链 zlib。体积与部署简易性是明确优先级。
6. **验收纪律**。不接受"编译通过"代替功能验证；每项改动要有安装版端到端证据（日志三字段 + 目检）；冒烟不过禁止打包。

## 2. 系统架构

### 2.1 模块图

```
flameshot.exe（单实例，KDSingleApplication 按用户全局锁）
│
├─ main.cpp ............ CLI 动词解析 / 第二实例转发 / quit 优雅退出
│
├─ FlameshortDaemon .... 常驻核心：托盘看护(watchdog 4-5s) / 热键注册(热生效) /
│                        notifyAlreadyRunning / shutdownForExit
│        └─ TrayIcon .... 托盘菜单（含"滚动截图"入口 B6）
│
├─ ScrollCapture（scrollcapture.cpp ~3400 行，本 fork 的核心资产）
│     ├─ RegionSelector ........ 多屏虚拟桌面全覆盖选区遮罩
│     ├─ ScrollRegionPicker .... 确认层：UIA 容器探测 + 自动吸附 + 八向缩放
│     ├─ 采集循环 .............. 滚轮注入 / 自适应步长 / stableFrame+SettleTuner /
│     │                        Esc 检查 / HUD re-raise / 400帧·32768px 上限
│     ├─ 拼接内核 .............. 行签名→列剔除→固定栏冻结→MAD 位移搜索→三态
│     │                        （细节见 [[滚动截屏算法设计]]）
│     └─ 后处理 ................ 静态侧栏/滚动条裁切(detectStaticSideBands) /
│                                客户区物理裁剪(clientRectOf)
│
├─ CaptureHud / RegionOutline . 反馈层：进度、徽章、选区高亮框
├─ CrashHandler ........ set_terminate + minidump 崩溃取证
└─ 标注编辑器（上游） .... 序号气泡最小 5×5、工具大小快捷键（T1/C 类）

installer/（独立构建，纯 Win32）
  setup.cpp ............ 解压 payload.bin → 静默安装 → HKCU Run → 优雅退出旧实例
  uninstaller.cpp ...... 同款优雅退出链
tools/ ................. 9 件测试运维工装（见 [[功能清单与交接]] §2.G）
```

### 2.2 进程与生命周期设计

- **常驻模型**：daemon 开机自启（HKCU Run），托盘看护每 4-5s 轮询图标，丢失自动重建（E1）。
- **单实例**：第二实例启动 → 单实例锁拒绝 → 转发参数给主实例 → 托盘气泡提示（D2/D3）。
- **退出协议**：`flameshot.exe quit` → 主实例 `shutdownForExit()` → 托盘 NIM_DELETE → 250ms 后退出；`m_shuttingDown` 阻止看护复活。安装/卸载器先走这条链，6s 后才强杀兜底（E3/E4）——这是根治"托盘幽灵图标"的设计。
- **拉起方式**：必须经 explorer 间接启动（脱离工具会话 Job 连坐），见 [[功能清单与交接]] §6 坑 1。

### 2.3 设计上的分层思想

**采集（物理层）与反馈（视觉层）严格分离**：采集循环里所有坐标是物理像素；HUD/高亮框只是只读投影。采集期间不冻结系统、不抢焦点（HUD re-raise 看护只救自家 UI，不动目标窗口 z-order）——这是"采集不干扰被截对象"原则的落地。

## 3. 滚动截图功能设计思路

### 3.1 设计目标

用户框选一个区域 → 软件自动滚动 → 输出一张**无重复、无缝隙、无杂质**的长图，全程可见、可中止、结果质量可读。三句用户语言对应三条硬指标：

| 用户语言 | 硬指标 | 判定（[[功能清单与交接]] §5） |
|---|---|---|
| "图是完整的" | 无缺口无重复 | 首帧高 + (N-1)×dy = 输出高 |
| "图是干净的" | 无侧栏/滚动条/壁纸混入 | 目检 + 静态侧栏裁切日志 |
| "结果是可信的" | 不静默失败 | `degraded=0` + `stopped: reached bottom` + 绿徽章 |

### 3.2 五阶段流水线（设计骨架）

```
① 选区          RegionSelector 全虚拟桌面遮罩，物理坐标
② 确认          ScrollRegionPicker：UIA 探测滚动容器 → 自动吸附为初始选区；
                选区∩目标窗口客户区（物理裁剪，防壁纸/任务栏/邻窗）
③ 回顶          纯滚轮回顶（不依赖 Ctrl+Home）+ 基准帧稳定化（防 hover 误判）
④ 采集循环      SendInput 滚轮注入 → 自适应步长 → stableFrame 等稳定帧
                （SettleTuner：4 安静帧收紧 90+150ms，迟重绘回退 150+240ms）
                → 拼接内核三态判定 → 到底（连续2帧无位移×三种滚动模式+UIA 位置）
⑤ 输出          拼接完成后：静态侧栏/滚动条逐列颜色距离检测裁切 →
                直接存 PNG + 剪贴板（不进标注，SPEC 契约）→ 徽章 + HUD 结果
```

每阶段的算法细节、参数依据、调试开关**不在此重复**，权威来源：
- 拼接内核数学与全部常量依据 → [[滚动截屏算法设计]] §3–§5
- 交互层与鲁棒性（远程检测/多屏/上限/吸附）→ [[功能清单与交接]] §2.A/B
- 每条设计当时为什么这么定 → [[滚动截屏调研]] §5 选型、§8–§10 补充

### 3.3 关键设计决策表（决策依据可溯源）

| 决策 | 被否掉的备选 | 为什么 | 出处 |
|---|---|---|---|
| 行签名 + 整数位移搜索 | OpenCV matchTemplate / ORB+RANSAC | 场景只有垂直平移无旋转缩放；OpenCV 体积+35MB；SPEC 冻结纯 QImage | 调研 §5.1 |
| 静态列/侧栏逐列剔除 | 全宽匹配（v1 实锤失败） | 固定侧栏在任何位移上"完美匹配"→多 dy 同分 | 调研 §4 共识 2 |
| 固定栏**只判一次冻结** | 逐帧重判 | 偶发 14px 误判会让单道接缝错位（实测到） | 算法 §3.3 |
| 三态输出 | 单一 dy 值 | "到底"和"没测准"必须可区分，否则静默腰斩 | 调研 §4 共识 5 |
| MAD==0 才提前退出 | "够好就停" | 相邻 1px 停止 → 每道接缝累积 1px 缝隙（实测 599 vs 600） | 算法 §3.5 |
| 颜色距离判侧栏（非灰度） | 灰度比较 | #1f6feb 蓝与 #238636 绿灰度同值，灰度判据会漏 | 实施记录 16 轮 |
| 滚轮注入为主，UIA 只探测+吸附 | UIA ScrollPattern 步进 | ScrollPattern 不能控制步长粒度，注入+像素测量更通用 | 实施记录 13 轮 |
| SettleTuner 自适应等待 | Cap 式固定 600ms | 无动画原生控件可收紧至 90+150ms 提速 ~40%，平滑滚动页保持保守 | 实施记录 17 轮 |
| 远程桌面红灯终止 | 照常采集 | 视频流无滚动容器+压缩噪声毁匹配，原理性不支持，白跑几十秒 | 实施记录 14 轮 |

## 4. 行业对标与开源参考（是否符合行业标准）

### 4.1 参考了哪些开源项目、各取了什么

| 开源项目 | 平台 | 本实现吸收的设计 |
|---|---|---|
| **ShareX**（Windows 行业标杆，`ScrollingCaptureManager.cs`） | C# | 四种滚动模式自动回退链；红/黄/绿三色质量分级；`AutoIgnoreBottomEdge` 固定底栏剔除；先回顶（AutoScrollTop）；采集区可见高亮框；托盘菜单入口 |
| **deepin-screen-recorder**（Qt 同门） | C++/Qt | 固定头尾栏"逐行是否变化"判定法；匹配分低明确报错给可操作建议 |
| **wayscrollshot**（mark-shot 系） | Wayland/Rust | 静态侧栏带剔除（本实现列采样方案的直接原型）；col-sample 的"预测偏移向外扩散"搜索 |
| **CaptureOCR** | Windows/Python | 行签名压维；右侧 8% 滚动条排除；歧义检测（best 不显著优于次优即判失败）；H/2 搜索上限 |
| **Cap**（PR #2097，Rust 真实端到端） | Win/macOS | 步数/高度双上限防失控；每步固定等待平滑滚动的思路（本实现改为自适应 SettleTuner，更优） |
| **zengfw/LongScreenShot** | Android/C | 多行验证防单行撞色（40 行 → 本实现签名更密取 32 行） |
| **白云截屏** | Android/Kotlin | 失败保护产品化表述："证据不足时提示复核而不是静默输出错位图" |
| **Picsew** | iOS/TS | 录屏流水线（关键帧选择/插播过滤）——**结论是不采用**（我们是同步逐帧，条件更好），但"插播污染帧丢弃"思想用于迟重绘回退 |
| **Scrollie / GoFullPage** | Web | "忽略状态栏默认开"；懒加载预滚——后者有意不做（取舍记录在案） |

各项目源码/文档链接见 [[滚动截屏调研]] §7。

### 4.2 符合行业标准的情况（三维结论）

对照行业六条共识（调研 §4）逐条对齐；2026-11-15 按**可靠性 / 性能 / 兼容性**三维重新核对（ShareX 官方文档 + 2026 评测 + Cap PR 全文，详见 [[滚动截屏调研]] §10）：

- **可靠性 ✅**：三态结果、非滚窗口 5s 静帧返回、Esc 中止、400帧/32768px 上限、崩溃取证。
- **性能 ✅**：~0.7s/帧，采集不独占输入，无动画页 SettleTuner 收紧至 90+150ms。
- **兼容性 ✅**：浏览器长页 / Electron 自定义容器（ChatGPT）/ 原生 Win32 控件 / 高 DPI 多屏 / 老式消息滚动窗口。

**五项超出行业最优**：崩溃取证（minidump）、静态元素自动剔除（ShareX 官方仍列为"已知限制，建议用户自己框小"）、sticky 侧列自动裁切（Cap 官方承认的缺陷）、SettleTuner 自适应等待（行业无人做）、远程桌面提前红灯（行业普遍白跑后失败）。
**两项有意不做**（记录在案的取舍，勿当 bug 修）：懒加载预滚（桌面应用未知时长，耗时翻倍）、长图进标注编辑器（SPEC 冻结 v1 不做）。

### 4.3 演化路径（为什么现在的长这样）

```
v1 底部横带全像素 SAD（自创）→ 测试页通过但真实页面静默腰斩
  → 第 2-5 轮：调研 8 个开源项目 → 六条行业共识 → v2 内核重写（融合四家之长）
  → 第 8-12 轮：交互件（确认层/HUD/多屏/热键）与鲁棒性（到底判定/回顶/自适应步长）
  → 第 13-18 轮：用户实测驱动的收口（UIA 吸附/静态侧栏裁切/客户区物理裁剪/
     托盘优雅退出/上限提示/三维对标确认）
```

**方法论沉淀**：测试页验证 ≠ 真实验证；每次"修不动"时正确动作是回行业找共识，而不是继续调参（v1 的教训）。

### 5.2 问题排查链（照抄）

1. `flameshot scroll --probe` → 看目标窗口有没有被识别到滚动容器（UIA 层面）
2. `python tools/scroll_run.py sticky.html <tag>` → 复现 + 抓日志
3. 看日志三字段：`Frames= / degraded= / stopped:` + `dy` 序列（[[功能清单与交接]] §5 判定标准）
4. 还不够 → `FLAMESHOT_SCROLL_VERBOSE=1` `FLAMESHOT_SCROLL_DUMP=<dir>` 逐帧落盘分析（[[滚动截屏算法设计]] §7）

### 5.3 新增功能标准流程

[[SPEC]] 立票据 → 实现 → `selftest` → 构建版冒烟（不过禁止打包）→ 打包链（交接 §4.0–4.2，逐条执行）→ 安装版端到端 + 目检 → 桌面交付 → [[实施记录]] 登记证据 → 本套文档同步更新（功能清单 §2 加行、本文 §3.3 决策表加行）。

### 5.4 禁止事项（历史实锤）

- 引入 OpenCV / 重型依赖（SPEC 冻结）
- 用 `;` 串接打包命令（旧二进制进安装包，12 轮实锤）
- 以 mock/局部成功替代完整验收（用户红线）
- 直接 `SetCursorPos` 模拟拖选（不产生 WM_MOUSEMOVE）
- 强杀 daemon（产生托盘幽灵；用 `flameshot quit`）
- 中文窗口标题走 shell argv（编码损坏；用 `run_cn_target.py`）

## 6. 设计边界（勿越界修补）

| 边界 | 性质 | 依据 |
|---|---|---|
| 远程桌面视频流不支持 | 原理性（无滚动容器+压缩噪声） | 红灯检测已做提前告知 |
| 懒加载图片可能不全 | 有意取舍（预滚耗时翻倍） | 调研 §10.3 |
| 平滑滚动 ~0.7s/帧 | 物理约束（必须等动画） | SettleTuner 已覆盖可收紧场景 |
| 长图不进标注 | SPEC 冻结 | 如需按 [[功能清单与交接]] §8 做轻量入口 |
| 固定栏 >35% 帧高不排除 | 防整页纯色误判 | 算法 §6 |

## 7. 后续演进规划（2026-11-15 评估，按边际收益排序）

**总体判断**：功能层面已收敛到行业最优档（三维对标见 §4.2），剩余大项不多；真正值得优先投入的是**维护性与工程质量**。

### 7.1 工程质量与维护性（最该做，收益最大）

| 优先级 | 项目 | 现状问题 | 建议做法 |
|---|---|---|---|
| ★★★ | **拆分 `scrollcapture.cpp`** | ~3400 行单文件装了选区层/确认层/HUD/采集/拼接/后处理六块职责，是维护最大瓶颈 | 拆成 `scroll_picker.cpp` / `scroll_capture_loop.cpp` / `scroll_stitch.cpp` / `scroll_hud.cpp` 等 5-6 个文件，对外接口不动。纯机械重构，风险低 |
| ★★★ | **自动化回归固化** `tools/release_check.py` | selftest + `scroll_run.py` 冒烟靠人工纪律，十八轮里多次靠自觉 | 一键脚本：selftest → sticky.html 冒烟 → 日志三字段**机器判定**（`degraded=0` + `stopped: reached bottom` + 高度吻合公式自动验算）→ 全绿才放行打包。把"冒烟不过禁止打包"从纪律变成机器闸门 |
| ★★ | **git 版本纪律** | 已建立（2026-11-15 起）：origin = `github.com/zaggerj/flameshot`（用户 fork），upstream = flameshot-org；交付打 tag `v15.0-zagger.<轮次>` 并 push（首个 `v15.0-zagger.21`） | 纪律延续即可，勿用 force push |
| ★★ | **安装器签名** | setup.exe 未签名，分发他人会被 SmartScreen 拦截 | 内部分发自签名证书即可；对外分发才需购买证书 |

### 7.2 功能演进（按用户价值排序）

1. **横向滚动**——唯一核心能力缺口（Snagit 卖点，开源界也少有做好）。拼接内核需支持二维位移，建议三步走：检测到横向容器先提示不支持 → 纯横向 → 混合
2. **长图轻量后处理**（裁剪/分段另存）——不进完整标注画布，符合 SPEC 边界
3. **`--probe` 配置向导**——每窗口滚动容器列表可视化，点选容器即完成框选
4. **懒加载可选预滚**（默认关，用户设置项）
5. **SettleTuner 动态阈值**——从固定"4 安静帧"改为按页面特征自适应

### 7.3 体验补强（锦上添花）

- 滚动参数用户可见配置（步长/延迟/上限，现为代码常量或环境变量）
- 版本更新检测（当前升级=重跑 Setup）
- 中文界面（上游 i18n 体系在，成本主要是翻译）

### 7.4 明确不做（护栏，防跑偏）

- ❌ OpenCV / 特征点匹配——铁律 5，SPEC 冻结
- ❌ 长图进完整标注编辑器——SPEC 冻结；需求由 §7.2-2 轻量入口承接
- ❌ 远程桌面视频流支持——原理性不可行，红灯检测已是正确答案

**选择建议**：只挑一件 → §7.1 的 `release_check.py` + 拆文件（功能已稳，最大风险是"改坏而不自知"，机器闸门+模块化是长期保险）；只挑一件用户可感知 → 横向滚动。任何新方向先过本文 §1 铁律再立项。
