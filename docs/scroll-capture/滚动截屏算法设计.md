# 滚动截屏算法设计

设计总纲：[[总体设计]] ｜ 调研依据见 [[滚动截屏调研]]，验收证据见 [[实施记录]]。

## 1. 一句话

**每帧压成 48 列行签名 → 剔掉不动的列和固定头尾栏 → 在剩余列上做单参数（垂直位移）搜索 → 三态输出（匹配 / 没动 / 匹配失败）。**

## 2. 为什么不是"取一条横带做 SAD"

v1 的做法有四个结构性缺陷，全都不是"参数没调好"，而是方法选错了：

| 缺陷 | 后果 |
|---|---|
| 匹配带固定在底部 420px | 落在纯色区时多个 dy 同分，测出 287 而非 300 |
| 采样跨全宽 | 右侧滚动条每帧都在变，是纯噪声 |
| 统计只在一条带 | 左侧固定侧栏不参与，无法识别；固定底栏会污染 |
| `dy≈0` 既表示"到底了"也表示"没测准" | **静默截断**，用户拿到一张腰斩的图却看不出来 |

行业里没有一个成熟实现是这么干的。

## 3. 流水线

```
抓帧 (BitBlt 精确选区)
  └─ buildProfile         H × 48 的灰度行签名
      └─ analyseColumns   逐列 activity / variance
          └─ usableColumns  剔掉静态侧栏、纯色列、滚动条
              └─ detectFixedBars   顶部/底部逐行恒定的行 = 固定栏（只判一次，之后冻结）
                  └─ sameRowMad     同位置逐行差 → 判断"到底没动"
                      └─ findShift   从预测位移向外扩散搜索
                          └─ 三态：MATCHED / NO_CHANGE / FAILED
```

### 3.1 行签名

- 取列：避开左侧 2% 与**右侧 8%（滚动条）**，等距 48 列
- 每列每行取 `(2·gray(x) + gray(x-1) + gray(x+1)) / 4`
- 内存：1664 行 × 48 列 = 80KB/帧；比较成本从 `O(W·H)` 降到 `O(H·48)`

### 3.2 静态列剔除（关键）

```
activity[c] = mean_y |prev[y][c] - curr[y][c]|     同一行位置比
variance[c] = 该列方差
usable     = activity >= 2 且 variance >= 3 的列
```

- `activity ≈ 0` → 固定侧栏 / 固定头尾栏 / 滚动条，**在任何位移上都"完美匹配"**
- `variance ≈ 0` → 纯色列，同样处处匹配，不带信息
- 剩下不足 8 列时，按 `activity*8 + min(variance,400)` 取前 12 列兜底

这一条是"多个 dy 同分"问题的根治手段。v1 靠"锚定 ±45px + 距离平局"打补丁，本质是在赌。

### 3.3 固定头尾栏

```
从顶部（底部）逐行算 rowDelta（只用可用列）
连续 rowDelta < 1.5 的行数 = 固定栏高度
上限 35% 帧高（防止整页纯色被当成一根大固定栏）
```

两个用途：

1. **测量区**收缩到 `[top, H-bottom)`，固定栏不参与打分
2. **写入区**收缩：只追加 `current[contentBottom-dy, contentBottom)`，固定尾栏**只在最后写一次**

第 2 点是本版最重要的修复。v1 追加的是"当前帧最后 dy 行"，当底部有 128px 固定栏时，每道接缝会重复写 128px 尾栏、并丢掉 128px 真内容 —— 实测 200 行只拼到 186 行。

**只判一次然后冻结**（`barsFrozen`）。逐帧重判会让某一帧偶然多出 14px 的"固定区"，把那一处接缝错开 14px（已实测到）。

### 3.4 三态输出

| 状态 | 判据 | 动作 |
|---|---|---|
| `NO_CHANGE` | 同一行位置 MAD ≤ 0.8 | 换滚动方式重试；三种方式都没动 → **真的到底** |
| `FAILED` | 最优候选 MAD > 24 | 先重抓（可能抓到动画中间态）2 次；仍失败 → 计数，3 次后停止并标 `degraded` |
| `MATCHED` | MAD ≤ 8 且不歧义 | 追加，置信 high；8 < MAD ≤ 24 → 追加但标 `degraded` |

`NO_CHANGE` 和 `FAILED` 分开是"不静默截断"的前提。日志与最终详情里会明说 `clean` / `degraded`。

### 3.5 位移搜索

- 搜索空间：`s ∈ [0, contentHeight - contentHeight/4]`
- 顺序：从**上一步位移**开始向外扩散 `p, p-1, p+1, p-2, p+2, …`
- 打分：整个可用重叠区按 ~300 行抽样，全部可用列，MAD
- 退出：**只在 MAD == 0 时提前退出**。允许"够好就停"会停在相邻 1px 上，每道接缝累积 1px 缝隙（实测到 599 vs 600）
- 歧义：最优与"距离 ≥8 的次优"比较，`best > 0.75 × rival` 判为歧义 → 降级

## 4. 参数与依据

| 常量 | 值 | 依据 |
|---|---|---|
| `PROFILE_COLUMNS` | 48 | CSDN/Scrollie 实测值；`H×48` 读取在一帧内可忽略 |
| `RIGHT_MARGIN_PERCENT` | 8 | CaptureOCR：滚动条 |
| `COLUMN_ACTIVITY_MIN` | 2 | 8bit 灰度，均值差 <2 即视为不动 |
| `COLUMN_FLAT_VARIANCE` | 3 | 同上 |
| `FIXED_BAR_MAX_PERCENT` | 35 | deepin 无上限；设上限防误判 |
| `MAD_PERFECT` | 2.5 | 亚像素噪声上限 |
| `MAD_GOOD` | 8.0 | 置信匹配上限 |
| `MAD_ACCEPT` | 24.0 | 超过即判失败 |
| `MAD_IDENTICAL` | 0.8 | "完全没动" |
| `SCORE_SAMPLED_ROWS` | 300 | 与候选数相乘后仍 <20ms |
| `MIN_SETTLE_MS` | 150 | 抓帧后最小等待 |
| `STABLE_SPAN_MS` | 240 | 必须连续 240ms 完全一致才采信 |
| `MAX_RESULT_HEIGHT` | 32768 | deepin 10000 太保守，ImageMagick 上限 65500 |

## 5. 性能

抓帧是唯一的大头：软件渲染桌面上 `BitBlt` 2217×1664 约 **75–80ms**，无法再降（Qt 的 `grabWindow` 是 106ms，因为它整屏抓再裁）。

因此优化的方向只能是**少抓帧**：

| 版本 | 抓帧/步 | 每帧耗时 | 48 帧总计 |
|---|---|---|---|
| 固定 1000ms 等待 + 短带搜索 | 9.6 | 2540ms | 122s |
| 连续静止判定 + BitBlt + 全重叠搜索 | 6.4 | 922ms | 87s |

`MIN_SETTLE 150 + POLL 60 + SPAN 240` 仍要求"连续 240ms 帧完全一致"，比原来固定 1000ms 更严格地证明动画结束，同时少了 1/3 的抓帧。

## 6. 已知边界（不假装支持）

1. 只支持主屏；框选本身只覆盖主屏，混屏无法选择
2. 懒加载 / 无限滚动：中途插入内容会让步长突变，可能标 `degraded`（不会再静默截断）
3. 重复卡片（整页同构）：歧义判定会命中，标 `degraded`
4. 长图不进标注界面（v1 契约）
5. 固定栏超过帧高 35% 时不排除

## 7. 调试开关

| 环境变量 | 作用 |
|---|---|
| `FLAMESHOT_SCROLL_VERBOSE=1` | 每步 dy/mad/rival/bars/cols + 分段耗时 |
| `FLAMESHOT_SCROLL_DUMP=<dir>` | 落盘每一帧 PNG |
| `FLAMESHOT_SCROLL_MAX_FRAMES` | 帧数上限 |
| `FLAMESHOT_SCROLL_MAX_HEIGHT` | 结果高度上限 |
| `FLAMESHOT_SCROLL_FROM_TOP=0` | 关闭"先回顶"探测 |
| `FLAMESHOT_SCROLL_IGNORE_FIXED_BARS=1` | 关闭固定栏排除（复现旧行为，用于对照） |
