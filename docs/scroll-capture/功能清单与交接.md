## 4. 构建 / 打包 / 交付全流程（含打包前环境准备，照抄即用）

### 4.0 打包前环境准备（Pre-flight，缺一不可，每项都踩过坑）

#### 4.0.1 工具链就位

| 依赖 | 版本/路径 | 说明 |
|---|---|---|
| MSYS2 MinGW-w64 | `/d/install/Scoop/apps/msys2/current/mingw64/bin`（即 `D:\install\Scoop\apps\msys2\current\mingw64\bin`） | g++ **16.2.0**，编译器 + windres + 静态 zlib 都从这里来 |
| Qt | **6.12.0**（随 MSYS2 mingw64 安装） | CMake 构建时由 toolchain 文件定位 |
| CMake / Ninja | **4.4.5** / Ninja | build/ 与 build-selftest/ 已配置好，平时只需 `ninja` 增量 |
| Python | 任意 3.x（内置 zlib） | 跑 `make_payload.py`、`scroll_run.py` |

**关键点：工具会话的 shell 状态不持久**——每个新的 Bash/PowerShell 会话都必须重新 `export PATH="$M:$PATH"`，否则 `ninja/windres/g++` 全部找不到。

```bash
M=/d/install/Scoop/apps/msys2/current/mingw64/bin; export PATH="$M:$PATH"
g++ --version | head -1   # 应输出 16.2.0
ninja --version            # 能出版本号即 PATH OK
```

#### 4.0.2 stage/ 依赖目录（一次性资产，平时不动）

`stage/` 里除 exe 外的 **91 个文件**（Qt6*.dll、libgcc/libstdc++/libbrotli 等 mingw 运行库、`generic/ iconengines/ imageformats/ networkinformation/ platforminputcontexts/ platforms/ styles/ tls/` 插件目录、flameshot.ico、空 flameshot.ini）是 **2026-11-14 一次性从 MSYS2 mingw64 准备的**。日常迭代**只替换 `stage/flameshot.exe`（和改了 CLI 时替换 `stage/flameshot-cli.exe`）**，其余不碰。只有升级 Qt 版本才需要重建 stage（从 `mingw64/bin` 重拷 Qt6*.dll + 相关 lib*.dll + `mingw64/share/qt6/plugins/` 各目录）。

安装器本体是**纯 Win32 程序（无 Qt 依赖）**，只静态链 zlib 解压 payload.bin，所以 Setup.exe 体积可控、任何机器可跑。

#### 4.0.3 打包前检查清单（顺序执行，任何一步不过就停下排查）

1. **无残留进程干扰**：`tasklist | grep -i flameshot`——有旧 daemon 没关系（安装器会 `quit` 优雅退出它），但要确认没有卡死的半实例；若强杀过进程，先跑 `tools/tray_sweep.py` 清托盘幽灵。
2. **构建产物新鲜**：改完源码先 `ninja -C build flameshot`，再核对 `ls -la build/src/flameshot.exe` 时间戳**晚于最后一次源码修改**；ninja 输出里出现实际 recompile 才算数。
3. **自检通过**：`ninja -C build-selftest && ./build-selftest/src/flameshot-cli.exe selftest`（picker + 序号 marker 全绿）。
4. **构建版端到端冒烟**：跑一次 `python tools/scroll_run.py sticky.html <tag>`，日志必须满足 §5 判定标准（`degraded=0`、`stopped: reached bottom`、高度吻合公式）。**冒烟不过禁止打包**——十二轮实锤教训：打包了没验证的旧二进制。
5. **CLI 同步检查**：若本迭代改了 CLI/自检相关代码，记得连 `build-selftest` 的 flameshot-cli.exe 一起重拷进 stage。

## 5. 验证判定标准（照抄即用）

一次成功的滚动截图，日志（`%LOCALAPPDATA%\Flameshot\logs\flameshot.log`）应满足：

```
Frames=N dy=[300@0.0,300@0.0,...] bars=topX/bottomY degraded=0 stopped=reached bottom driver=wheel
Scrolling capture: <path> (WxH, N frames, clean), stopped: reached bottom
```

- `degraded=0` + `stopped: reached bottom` = clean 全绿
- `dy` 全部相等且 mad=0.0 = 拼接零误差
- 高度吻合公式：`首帧高 + (N-1)×dy = 输出高`（精确无缺口无重复）
- 目检：长图无重复侧栏块、无滚动条滑块列、无壁纸/任务栏

## 6. 环境坑（**下一个 agent 必读**，全部踩过实锤）

1. **工具会话 Job Object 连坐杀**：Bash/PowerShell 工具会话结束时杀死该会话启动的所有子进程（GUI 也逃不掉）。要拉起存活的 daemon/测试窗口，必须 `Start-Process explorer.exe -ArgumentList '"<lnk 或文件路径>"'`（explorer 常驻，目标由 explorer 启动，脱离 Job）。**教训升级：任何"进程静默死亡"先查 Job 杀死，再查代码。**
2. **拖选必须 SendInput 绝对移动**：`SetCursorPos` 不产生 WM_MOUSEMOVE，RegionSelector 判 cancelled。
3. **x64 键盘 INPUT 结构必须 40 字节**（KBINPUT 补 8 字节 pad），否则 SendInput 静默失败。
4. **中文窗口标题经 bash→python argv 编码损坏**（`"@xx-记事本"` 找不到窗口）：用 `tools/run_cn_target.py` 从 UTF-8 文件读标题。
5. **打包链禁止用 `;` 串接**：短路后旧二进制被装进安装包（十二轮实锤）。
6. **build 目录 exe 缺 Qt DLL 时 `--version` 退出码 127**：环境假象，非代码 bug；带 MSYS2 PATH 跑或用安装版验证。
7. **托盘"幽灵图标"**：进程被强杀（TerminateProcess/任务管理器）留下的图标，hover 时被 Explorer 清理；不是软件崩溃。防再生靠 E3/E4 优雅退出链路；存量清理用 `tray_sweep.py`。
8. **lupdate 在本机跑不起来**：MSYS2 `lupdate.exe` 缺 `Qt6Qml.dll`，exit 127 且无输出；手工维护 `.ts` 或装 `mingw-w64-x86_64-qt6-declarative`。
9. **Win11 记事本也有平滑滚动**：真正瞬时滚动的测试窗口是经典 Win32 控件（regedit 的 ListView）。

## 7. 已知限制（如实，勿当 bug 修）

| 限制 | 原因 | 处理 |
|---|---|---|
| 远程桌面/视频流窗口（UU远程等）不能滚动截图 | 视频流无滚动容器、滚轮转发、压缩噪声毁匹配，原理性不支持 | 已做红灯检测提前告知"请在远程机器上装 Flameshot" |
| 懒加载图片可能不完整 | 有意不做预滚（桌面应用未知时长，耗时翻倍） | 浏览器场景由 UIA 步进覆盖；记录在案 |
| 平滑滚动页 ~0.7s/帧 | 必须等动画结束才能取稳定帧（行业同样如此，Cap 用 600ms 固定等待） | SettleTuner 已把无动画页收紧到 90+150ms |
| 长图不进标注编辑器 | SPEC 明确 v1 不做 | 如需可做"长图→裁剪/另存"轻量入口 |

## 8. 后续可做（优先级规划，2026-11-15 评估；权威来源=[[总体设计]] §7）

**优先级总原则**：功能已收敛到行业最优档，优先投入**维护性与工程质量**。

1. **工程质量（收益最大，先做）**：
   - 拆分 `scrollcapture.cpp`（3400 行 → 5-6 个文件，对外接口不动，纯机械重构）
   - `tools/release_check.py` 自动化回归闸门：selftest → 冒烟 → 日志三字段机器判定 → 全绿才放行打包
   - git tag 版本纪律（`v15.0-zagger.N` ↔ 实施记录轮次一一对应）
   - 安装器签名（内部分发自签名即可）
2. **功能演进（按用户价值）**：横向滚动（唯一核心缺口，三步走：提示不支持→纯横向→混合）→ 长图轻量后处理 → `--probe` 配置向导 → 懒加载可选预滚 → SettleTuner 动态阈值
3. **体验补强**：滚动参数用户可见配置 → 更新检测 → 中文界面
4. **明确不做（护栏）**：OpenCV/特征点（铁律）、长图进完整标注（SPEC 冻结）、远程桌面视频流（原理性）

## 9. 接手注意事项

- **验收纪律**（继承 [[SPEC]] §3）：不接受"编译通过"代替功能验证；每票据实测证据；未通过不得标完成。
- 任何滚动截图问题先跑 `flameshot scroll --probe`（列窗口+容器），再跑 `scroll_run.py`，最后看日志 `Frames=/degraded=/stopped=` 三字段。
- 用户实际场景提醒：用户常用 **ChatGPT 桌面窗口**与浏览器长页；用户会在真实桌面上自己操作验证，确认层/ESC 是真人交互，自动化测试时用 `FLAMESHOT_SCROLL_CONFIRM=0` 跳过交互层。
- 桌面交付物在验证完成后再同步；`Flameshot-SHA256.txt` 与安装版哈希保持一致。
