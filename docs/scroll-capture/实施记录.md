### T3 期间定位并修掉的真实缺陷

| # | 现象 | 根因 | 处理 |
|---|---|---|---|
| 1 | 长图右侧整片黑、每帧一条 100px 黑带 | `QImage` 带 `devicePixelRatio=1.5`，`QPainter::drawImage` 按设备无关尺寸绘制，1302×299 的帧带被画成 868×199 | `grabFrame` 重置 dpr 为 1.0；`appendStrip` 显式传目标矩形 |
| 2 | 位移偶尔测成 287/284 而非 300，行被压扁 13px | 采样带落在纯色区域，多个 dy 得分为 0，搜索选错 | 改为「以预期步长为锚 ±45px 窗口 + 全分辨率采样 + 距离平局判定」 |
| 3 | 抓帧早于平滑滚动动画结束 | 实测一次 2 格滚动需 ~1000ms 才静止 | 最小等待 1000ms + 稠密指纹（2 行/3 列）判定静止 |
| 4 | Esc 快速按下抬起被漏掉 | 只判 `GetAsyncKeyState` 的 0x8000 位 | 同时接受 0x0001「自上次调用后按下过」锁存位 |
| 5 | Chromium 忽略注入滚轮 | `SetCursorPos` 不产生 `WM_MOUSEMOVE`，页面不知道悬停目标 | `SendInput` 绝对移动后再滚；保留 PageDown / `WM_MOUSEWHEEL` 降级链 |

**已确认的降级链**（本项目环境实测有效顺序）：`SendInput` 绝对移动 + 滚轮（有效，300px/2 格）> PageDown（有效，1130px，位移过大易丢重叠）> `PostMessage(WM_MOUSEWHEEL)`（本机无效，保留给其他应用）。

**v1 限制（如实记录，不假装支持）**：懒加载 / 无限滚动 / 动画视频会漏帧或无法判定终点；只支持主屏；长图不进标注界面。

## T3-v2 拼接内核重写

v1 的实现（取底部一条横带做全像素 SAD）在我们自己造的测试页上能过，**但那个测试页没有固定头尾栏、没有滚动条干扰、步长恒定**。真实页面三者都不满足。先做了行业调研（[[滚动截屏调研]]），再按调研结论重写（算法见 [[滚动截屏算法设计]]）。

### 调研结论（六条共识）

1. 不在全分辨率上做二维搜索，先压成行签名 / 窄带 / 列采样
2. 匹配前**剔除不动的区域**（静态侧栏、固定头尾栏、滚动条）
3. 从预测偏移向外扩散搜索
4. 匹配要验证、要报置信度，可疑就明说
5. **"到底了"和"匹配失败"必须是两个状态**
6. 固定头尾栏只写一次

参考实现：ShareX（Windows，最直接对标）、deepin-screen-recorder（Qt 同门）、wayscrollshot（八带签名 + 静态带剔除）、Picsew（录屏转长图流水线）、CaptureOCR（行签名 + 歧义检测）、zengfw/LongScreenShot（40 行验证）、白云截屏（失败保护）。

### 本版修掉的缺陷

| # | 现象 | 根因 | 处理 |
|---|---|---|---|
| 1 | 有固定底栏的页面，每道接缝重复写尾栏、丢内容 | 追加的是"当前帧最后 dy 行"，固定尾栏不在滚动内容里 | 检测固定尾栏，追加区间收缩到 `[bottom-dy, bottom)`，尾栏最后只写一次 |
| 2 | 某一处接缝错开 14px，行距出现 149/121 | 固定栏**逐帧重判**，某帧偶然多出 14px 固定区 | 只在第一对帧判定，之后冻结 |
| 3 | 前三步测出 599 而非 600 | 允许"MAD ≤2.5 就提前退出"，停在相邻 1px 上 | 只在 MAD == 0 时退出 |
| 4 | 重抓帧后下一步基准错乱 | 重抓后更新了图像但没更新行签名 | 签名跟随帧一起更新 |
| 5 | 每次抓帧 106ms，48 帧里 39s 在抓帧 | Qt `grabWindow` 整屏抓取后裁剪 | 改 `BitBlt` + DIB section 精确选区（75ms），并减到 6.4 次/步 |
| 6 | 采集最长 90s 无任何界面反馈，像卡死 | 没有进度提示 | 新增 `CaptureHud` |

### v2 仍存在的边界

1. 只支持主屏（框选层本身只覆盖主屏）
2. 懒加载 / 无限滚动会让步长突变，可能标 `degraded` —— 但不会再静默截断
3. 整页同构的重复卡片会触发歧义判定 → 标 `degraded`
4. 固定栏超过帧高 35% 时不排除
5. 长图仍不进标注界面

### 为此补的两处代码（缺一则"装上了但按了没反应"）

1. **`daemon` 子命令**。原先只有 `launcher` 会启动托盘 + 全局热键，而它每次都弹一个启动器窗口；`flameshot.exe` 无参数启动则什么都不做（`main.cpp` 的分支直接落到 `finish`）。于是"开机自启"实际等于没有热键。新增 `flameshot daemon`：只建托盘与热键，不显示任何窗口；同时把 `setStartupLaunch()` 写的自启命令改成 `"<exe>" daemon`，`verifyLaunchFile()` 按同一字符串比较（原实现比较裸路径，改命令后会误判失败）。
2. **`forceForeground()`**（`src/utils/windowforeground.h`）。托盘子进程被热键唤起时并不持有前台权，Windows 会挡掉 `SetForegroundWindow`，选区窗口画出来了却拿不到键盘焦点 —— 表现为 **Esc 关不掉、Ctrl+C 没反应**。用 `AttachThreadInput(fgThread, myThread, TRUE)` + `SetForegroundWindow` + `SetFocus` 绕过，退出前 detach。`Flameshot::gui()` 的 Windows 分支与滚动截屏的 `RegionSelector` 都接了这个。

### 坑与边界（如实记录）

### G. 本轮踩到的坑（如实记录）

- **载荷格式不匹配**：`make_payload.py` 用 `zlib.compress`（带 zlib 头 `78 DA`），安装器用 `inflateInit2(-MAX_WBITS)`（裸 deflate）→ 每个条目都解压失败，日志只说"无法写入文件"。改成 `MAX_WBITS + 32`（自动识别 zlib/gzip 头）。
- **ini 编码**：`writeTextFile` 直接把 `wchar_t` 写盘 → UTF-16 文件；Qt 的 ini 是 UTF-8，读不到覆盖项。改为 UTF-8 无 BOM 输出，实测键值生效。
- **安装包缺 DLL**：只加 `-static-libgcc -static-libstdc++` 仍动态依赖 `libwinpthread-1.dll`，双击报 127。改 `-static` 全静态链接，`objdump -p` 确认只剩系统 DLL。
- **`GetDpiForWindow` / `GetDpiForSystem`** 是 Win10 1607+ 导出，直接链接会让旧系统报"找不到入口点"。改为 `GetProcAddress` 运行时解析 + 屏幕 DC 兜底。
- **卸载器不该是安装包的副本**：复制 38MB 安装包当卸载器，安装后占 124MB。改为独立编译 380KB 卸载器（`installer/uninstaller.cpp`），安装后 89MB。
- **pngcrop.py**：`shot.exe` / `crop.exe` 在本机会挂死，`Add-Type`/`System.Drawing` 被安全策略拦截，故用 stdlib 写了 PNG 解码+裁剪（`tools/pngcrop.py`），用于本轮所有界面截图核对。

## J. 滚动截屏：从"滚桌面"到"识别滚动区域"（2026-11-14 21:00–21:15）

前面的 H 节交付时，滚动截屏只有"选区 + 注入滚轮 + 画面差分"三件事，**没有任何一处判断这块区域到底能不能滚**。用户点完按钮看到的是"屏幕闪一下、得到一张和选区一样大的图"，判定功能没做。核对 20:53 的日志，锅在 `Scroll target window: Program Manager`：单点取窗口取到了桌面壁纸。

### 改了什么

| 文件 | 改动 |
|---|---|
| `src/utils/scrolluia.h/.cpp`（新增，约 270 行） | UI Automation 封装：`attach(point)` 从 `ElementFromPoint` 向上找第一个 `ScrollPattern` 且 `VerticalViewSize<100` 的祖先；提供 `verticalPercent/viewPercent/scrollToPercent/scrollByPage/boundsPhysical` |
| `src/utils/scrollcapture.cpp` | ① `resolveScrollTarget()` 6×6 网格投票取代单点；② `attachScrollContainer()` 10 点采样找容器；③ 回顶改 `SetScrollPercent(0)`；④ 步进按 `view*0.45` 算；⑤ 到底用 `p+view>=99.4` 判定；⑥ 等叠加层消失再采样；⑦ 选区裁到屏幕内；⑧ 三处 HUD 中文提示；⑨ 新增 `diagnose()` |
| `src/main.cpp` | `scroll --probe` 参数，跑产品代码只读输出 |
| `src/CMakeLists.txt` | MinGW 链接 `uiautomationcore oleaut32`；MSVC 用 `#pragma comment(lib)` |
| `tools/scrollprobe.cpp`（新增） | 独立只读探针，和产品解耦的 A/B 对照 |

### 关键实现细节

1. **为什么必须用 UIA 而不是"滚一下看看"**：帧差只能证明"动了"，不能给出位置，也无法判断"这块区域能不能滚"。UIA 的 `VerticalScrollPercent` + `VerticalViewSize` 同时给出"我在哪"和"一屏占多少"，于是步长和终点都是算出来的，不是猜的。
2. **为什么容器矩形要单独记**：浏览器窗口矩形包含标签栏、地址栏、书签栏、侧边栏。滚轮落在这些地方不会滚页面。`BoundingRectangle` 给的是真正的滚动视口，与选区求交再取中心，滚轮才落在内容上。
3. **为什么保留滚轮路径**：VSCode 的部分面板、老 MFC 程序、自绘 UI 没有 ScrollPattern。降级不是"失败"，而是"用另一条路走"——`wheel-point` 已经算好，退回去也是滚内容区。
4. **`UIA_ScrollPatternNoScroll` 在 mingw-w64 头里缺失**，值固定为 -1.0，自己定义 `kNoScroll`。

## 第十六轮（2026-11-15 14:30–15:12）：长图侧栏重复 + 托盘六个图标的根因与修复

**用户证据**：①滚动长图左侧的 Codex 会话列表重复了十几次；②任务栏托盘里有 6 个一模一样的 Flameshot 图标。

### 根因 A：固定侧栏/滚动条被逐帧拼进长图

`stableFrame()` 取的是"窗口客户区"，客户区**包含**左侧会话列表；而列表不随内容滚动，于是每一帧的侧栏都被当成新内容追加一次。旧版只在**匹配**阶段剔除静态列（`usableColumns`），从没在**取像素**阶段剔除——所以匹配是对的、图是脏的。同理，右侧垂直滚动条的滑块每帧处于不同位置，也被逐帧拼入，形成一列重复的滑块。

### 修复 A：`detectStaticSideBands()`（scrollcapture.cpp）

用「首帧」与「第一个真正滚动后的帧」逐列比较：

- **颜色距离**而非灰度（`|ΔR|+|ΔG|+|ΔB|)/3`）：#1f6feb 蓝与 #238636 绿灰度几乎相同，灰度判据会把滚动内容误判为静止；
- **左带** = 从 x=0 起像素完全相同的连续列（≤45% 宽），且带内平均方差 ≥8（防止把纯白页边距当侧栏裁掉）；
- **右带** = 从右边界起"变化率 <60%"的连续列（≤25% 宽），并要求**内侧相邻列变化率 ≥75%**——这一条是安全阀：只有"左边是真滚动内容"时才认定右边是 gutter/滚动条，内容稀疏的页面不会被误裁；
- 保护：裁完剩下的宽度必须 ≥35%，否则两条带都放弃；
- 裁切在**拼接完成后**对画布做（因为带内像素逐帧完全相同，裁画布 ≡ 裁每一帧），日志记录 `Static column runs` / `Static side panel removed`。

### 根因 B：托盘六个图标 = 1 个活 + 5 个"死进程幽灵图标"

- `tools/trayprobe.exe`（新增，UIA 枚举通知区域）实测：**flameshot 图标 = 1，flameshot 进程 = 1**；
- 日志 `Tray icon created` 恰好 5 次（10:48 / 11:04 / 11:11 / 14:09 / 14:25），每次都是"先结束旧进程、再启动"——旧图标的所有者进程被 **TerminateProcess** 杀掉，没有走 `NIM_DELETE`，Explorer 就一直画着它；
- 根源在打包链：`installer/setup.cpp::stopRunningInstances()` 一直是 `TerminateProcess`。**每次升级都会留下一个幽灵图标**，今天升级 5 次 = 5 个。

### 修复 B：优雅退出链路

1. 新增 `flameshot quit` 动词：转发给主实例 → `FlameshotDaemon::shutdownForExit()` → 停看护定时器 → `m_trayIcon->hide()`（发 NIM_DELETE）→ 250ms 后退出；`m_shuttingDown` 阻止看护定时器把图标复活；
2. `installer/setup.cpp` 与 `uninstaller.cpp`：先 `flameshot.exe quit` 并轮询等待 6s，**仍在运行才** `TerminateProcess` 兜底；
3. 新增 `tools/tray_sweep.py`：用 SendInput 扫过通知区域，让 Explorer 逐个校验并丢弃已死的图标（不改进程、不重启 Explorer）。本轮清掉了积压的 5 个幽灵。
